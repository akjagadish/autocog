# arbitration

## System Prompt

You are a renowned cognitive scientist arbitrating between two theories across multiple experiments in the Decision Making (Binary Features) domain.

Each experiment was proposed alongside a metric and an expected outcome. For each experiment you are shown the design, the metric, both theories' predicted metric values (from simulated data), and the observed metric value on real data. The two theories are tagged by stable labels (e.g. "pi_5" and "pi_12") and the same labels are reused on each experiment's predictions.

Each metric value below is shown as `point_estimate (var=X)`, where `point_estimate` is `metric(data)` evaluated on the full pooled dataset and `var` is the population (between-subject) variance of the same metric re-applied per `subject_id`. The point estimate is the canonical scalar; `var` reports how consistent that estimate is across subjects (lower = more consistent). `var=n/a` means the metric could not be applied to a single-subject slice.

The goal of the arbitration is to surface theories that are task-invariant: that is, theories that can explain data across all experiments in the same domain. Perform a deep dive: which among the two theories better captures the observed data?Do not just look at the newest experiments, but look at all experiments together. If a theory is good at explaining all the data keep it. However, if the both theories are good at explaining some experiment but not all, then it might be a good idea to propose a completly new theory that can potentially explain all the data. It is often better to propose a new theory than to propose a new model. Even if one theory is clearly better than the other, instead of proposing a new model, you can propose a new theory that is a stronger competitor to the winning theory instead of proposing a new model. Only propose a new model if both theories are very good and you are confident that the new model will be better than the current one clearly distinguish the two theories.  Then issue a verdict: either "new_model" (keep the current theory description, but regenerate new predict / policy / parameter ranges such that they better capture the observed data across all experiments) or  "new_theory" (the current theory is degenerate; propose a brand-new theory that can better capture the observed data across all experiments). `target_theory_idx` is 1 if you are acting on the theory labelled "pi_5" (THEORY 1 below), or 2 if you are acting on the theory labelled "pi_12" (THEORY 2 below). Justify your choice.


## User Prompt

## EXPERIMENTAL DOMAIN
Subjects repeatedly choose between two fictitious products, A and B. Each option is described by a vector of binary expert ratings (each 0 or 1). Every experiment fixes its own feature count (via `validities` length) and per-expert validities; both are LLM-proposed. The validities are communicated to the subject in the instructions. Subjects pick whichever product they believe is of higher quality. There is no trial-by-trial correctness feedback.

## THEORY 1 — pi_5
Tally-then-TTB (Tally with Validity Tie-Breaker): Decision-makers first compare options by tallying the total number of winning features for each option, ignoring cue validities. If one option has strictly more wins, it is chosen. This captures the compensatory nature of decision-making when there is a clear majority of supporting cues. However, if the tally results in a tie, the decision-maker falls back to a non-compensatory 'Take-The-Best' strategy to break the tie, choosing the option that wins on the single most valid cue. This hybrid model preserves robust Tallying performance on unequal-tally trials while capturing deterministic validity-based tie-breaking on ambiguous trials.

def predict(parameters, stimulus, history):
    import numpy as np
    
    stim = np.asarray(stimulus, dtype=float)
    if stim.ndim != 2 or stim.shape[0] != 2:
        raise ValueError(f"Expected a (2, n_features) stimulus; got shape {stim.shape}.")
        
    a, b = stim[0], stim[1]
    val = np.asarray(parameters["validities"], dtype=float)
    
    # Tallying phase: count strict feature-wise wins
    a_wins = float(np.sum(a > b))
    b_wins = float(np.sum(b > a))
    
    score_a = a_wins
    score_b = b_wins
    
    # Tie-breaking phase: if tallies are equal, use TTB
    if a_wins == b_wins:
        cue_order = np.argsort(-val, kind="stable")
        for idx in cue_order:
            if a[idx] > b[idx]:
                score_a += 1.0
                break
            elif b[idx] > a[idx]:
                score_b += 1.0
                break
                
    scores = np.array([score_a, score_b])
    
    beta = float(parameters["beta"])
    epsilon = float(parameters["epsilon"])
    
    # Softmax choice rule with max-subtraction for numerical stability
    z = beta * (scores - np.max(scores))
    e = np.exp(z)
    p_core = e / np.sum(e)
    
    n_opts = p_core.shape[0]
    return (1.0 - epsilon) * p_core + epsilon * (np.ones(n_opts) / n_opts)

## THEORY 2 — pi_12
Probabilistic Strategy Mixture (Tallying and Take-The-Best) with Strong Tallying Bias

`predict(parameters, state, history) -> np.ndarray`:
def predict(parameters, stimulus, history):
    import numpy as np
    
    stim = np.asarray(stimulus, dtype=float)
    if stim.ndim != 2 or stim.shape[0] != 2:
        raise ValueError(f"Expected a (2, n_features) stimulus; got shape {stim.shape}.")
        
    a, b = stim[0], stim[1]
    val = np.asarray(parameters["validities"], dtype=float)
    
    p_ttb = float(parameters["p_ttb"])
    beta_tally = float(parameters["beta_tally"])
    epsilon = float(parameters["epsilon"])
    
    # Tallying prediction
    a_wins = float(np.sum(a > b))
    b_wins = float(np.sum(b > a))
    scores_tally = np.array([a_wins, b_wins])
    
    z_tally = beta_tally * (scores_tally - np.max(scores_tally))
    e_tally = np.exp(z_tally)
    p_tally = e_tally / np.sum(e_tally)
    
    # Take-The-Best (TTB) prediction
    order = np.argsort(val)[::-1]
    ttb_a, ttb_b = 0.5, 0.5
    for idx in order:
        if a[idx] > b[idx]:
            ttb_a, ttb_b = 1.0, 0.0
            break
        elif b[idx] > a[idx]:
            ttb_a, ttb_b = 0.0, 1.0
            break
    p_ttb_strat = np.array([ttb_a, ttb_b])
    
    # Fixed probabilistic mixture of the two pure strategies
    p_core = p_ttb * p_ttb_strat + (1.0 - p_ttb) * p_tally
    
    n_opts = p_core.shape[0]
    return (1.0 - epsilon) * p_core + epsilon * (np.ones(n_opts) / n_opts)

## EXPERIMENT 1 (proposed by pi_5)

### DESIGN
**Validities (n_features=5):** [0.9, 0.8, 0.7, 0.6, 0.5]

**Trial pairs (n=4):**
  trial 1: A=[1, 1, 1, 0, 0]  B=[0, 0, 0, 1, 1]
  trial 2: A=[0, 1, 1, 1, 0]  B=[1, 0, 0, 0, 1]
  trial 3: A=[1, 0, 0, 1, 0]  B=[0, 1, 1, 0, 0]
  trial 4: A=[0, 1, 1, 0, 0]  B=[1, 0, 0, 0, 1]

**Rationale:** To dissociate Tally-then-TTB (advocated) from the Probabilistic Strategy Mixture (competing), we exploit the competing model's upper bound on TTB reliance. On tied-tally trials, Tally-then-TTB deterministically uses the highest-validity cue to break the tie, allowing it to predict a very strong preference (approaching 100% depending on beta). In contrast, the Mixture model generates a 50/50 guess from its Tallying component on tied-tally trials, and its TTB component weight is strictly bounded by p_ttb <= 0.3. Consequently, the Mixture model is structurally constrained to predict at most a 65% preference for the TTB winner on these trials. By including tied-tally trials alongside unequal-tally baseline trials, we can robustly test if subjects exhibit deterministic tie-breaking that exceeds the Mixture model's mathematical limits.

**Computed schedule:** 4 unique pairs × 24 reps = 96 trials per subject.



### METRIC
Rationale:
This metric calculates the proportion of times the subject chooses the Take-The-Best (TTB) winner on trials where the simple tally of winning features results in a tie. The advocated Tally-then-TTB model deterministically uses TTB to break these ties, predicting a very high adherence to the TTB winner (close to 1.0, minus noise). The competing Probabilistic Strategy Mixture model uses a 50/50 tallying guess on these trials, and its TTB component is strictly bounded by p_ttb <= 0.3. Thus, the competing model can predict at most a 65% preference for the TTB winner on tied trials. This structural constraint guarantees a large, reliable gap between the theories.

    import pandas as pd
    
    tied_ttb_match = []
    
    for _, row in data.iterrows():
        a = np.array(row['option_a_ratings'])
        b = np.array(row['option_b_ratings'])
        
        a_wins = np.sum(a > b)
        b_wins = np.sum(b > a)
        
        if a_wins == b_wins:
            # Ties are broken by TTB in the advocated model.
            # The validities are strictly decreasing, so the highest validity
            # cue is simply the first one where options differ.
            ttb_winner = -1
            for idx in range(len(a)):
                if a[idx] > b[idx]:
                    ttb_winner = 0
                    break
                elif b[idx] > a[idx]:
                    ttb_winner = 1
                    break
            
            if ttb_winner != -1:
                tied_ttb_match.append(1 if row['response'] == ttb_winner else 0)
                
    if not tied_ttb_match:
        return 0.5
    return float(np.mean(tied_ttb_match))

## EXPERIMENT 2 (proposed by pi_12)

### DESIGN
**Validities (n_features=5):** [0.9, 0.8, 0.7, 0.6, 0.5]

**Trial pairs (n=4):**
  trial 1: A=[1, 1, 1, 0, 0]  B=[0, 0, 0, 1, 1]
  trial 2: A=[1, 0, 1, 0, 0]  B=[0, 1, 0, 1, 0]
  trial 3: A=[0, 1, 1, 1, 0]  B=[1, 0, 0, 0, 1]
  trial 4: A=[0, 1, 0, 1, 0]  B=[1, 0, 1, 0, 0]

**Rationale:** To dissociate the Probabilistic Strategy Mixture (advocated) from Tally-then-TTB (competing), we exploit a strict structural constraint in the competing model. Tally-then-TTB assigns a 1-point score difference to a 1-point tally advantage (e.g., 3 vs 2 winning features) and exactly the same 1-point score difference to a tied tally broken by the highest-validity cue. Thus, it is forced to predict identical choice determinism across both trial types. In contrast, the advocated Mixture model predicts strong preferences on 1-point tally advantages (driven by its Tallying component) but is strictly bounded to a weak preference (maximum 65%) on tied-tally trials because its Tallying component guesses 50/50 and its TTB weight is capped at 0.3. By including both 1-point tally advantage trials and tied-tally trials, we can demonstrate that subjects show high determinism on tally advantages but much lower determinism on ties—a quantitative pattern the advocated model naturally fits but the competing model cannot.

**Computed schedule:** 4 unique pairs × 24 reps = 96 trials per subject.



### METRIC
Rationale:
This metric calculates the difference in choice determinism between unequal-tally trials and equal-tally trials. The competing Tally-then-TTB model assigns exactly a 1-point score difference to the favored option in both trial types, predicting identical choice probabilities (metric ≈ 0). In contrast, the advocated Probabilistic Strategy Mixture model predicts highly deterministic choices on unequal-tally trials (driven by the Tallying component) but weakly deterministic choices on equal-tally trials (bounded by the low maximum TTB weight of 0.3), resulting in a large positive difference.

def metric(data: pd.DataFrame) -> float:
    import numpy as np
    
    def is_unequal(row):
        return sum(row['option_a_ratings']) != sum(row['option_b_ratings'])
        
    def favored_choice(row):
        a_sum = sum(row['option_a_ratings'])
        b_sum = sum(row['option_b_ratings'])
        if a_sum > b_sum:
            return 0
        elif b_sum > a_sum:
            return 1
        else:
            # Equal tally: tie-breaker is the first cue (highest validity)
            if row['option_a_ratings'][0] > row['option_b_ratings'][0]:
                return 0
            else:
                return 1

    unequal_mask = data.apply(is_unequal, axis=1)
    favored = data.apply(favored_choice, axis=1)
    is_favored = (data['response'] == favored)
    
    p_unequal = is_favored[unequal_mask].mean()
    p_equal = is_favored[~unequal_mask].mean()
    
    return float(p_unequal - p_equal)

    sum_a = data['option_a_ratings'].apply(sum)
    sum_b = data['option_b_ratings'].apply(sum)
